# 从实际执行记录提炼的依据

来源是本次会话可读取的最终脚本、基准 JSON、逐条事件日志、SQLite、回补标记、最终统计和用户纠正。未把摘要未提供的早期工具输出当作已核实证据。包中不包含原始日志、轨迹、设备标识、账号信息或截图。

## 成功的方法与证据

| 决策 | 实际依据 | 本 Skill 的处理 |
|---|---|---|
| 电脑脚本经 ADB 操作模拟器 | 原月采集器、core.process_card 和 events 中 pulled 事件 | 保留普通点击/滑动/返回与只读拉取，未引入未证实接口 |
| CSV 可用于 QGIS | 真实设备会话中的样本成功转换；精确轨迹数、点数和日期范围不公开 | 保留原转换公式与 GeoJSON/GPX/KML writer |
| 日期需要闭环选择 | 滚轮惯性导致选月偏移；read_picker_selection + choose_picker_target + 面板年月复核 | 保留 OCR 与二次校验，去除固定历史月份上界 |
| 月末卡片会漏 | audit_backfill_meta 记录旧 -30、新 -5；历史边界补测显示旧阈值会漏，具体年月不公开 | 保留 -5，添加底部合成卡片回归测试 |
| 地址截断导致重复 | stable_collisions 中同年同日时间距离，地址末段不同 | 保留年份+时间+距离键、UUID 合并，避免整段地址唯一去重 |
| sequence 不能作总数阈值 | 历史记录行数与最大 sequence 不一致，存在去重或迁移空号 | 月份范围与唯一 UUID 独立统计 |
| 定向重试确实补得回来 | 历史会话中重排慢项后确有补回，仍有少量未解决记录；精确数量不公开 | 提供保留原序号、限定日期的重试，不删除元数据 |
| 用户排除月必须保留 | 用户明确排除了个别月份 | 只在自用本次配置说明中保留，不写成所有用户的通用排除项 |

历史数据集跨越多个有数据月份，用户曾确认列表到最后一项，但仍有少量未解决记录，早期年份标记也存在疑点。活动月份、记录总数和遗留数量属于个人活动元数据，不公开；剩余数不是新用户任务的预期值。

基准文件保存 5 次成功拉取，平均约 5.1 秒/次动作；RESEARCH 中另有 1.7–2.3 秒估计，最终事件不少约 2–4 秒，但换月、UI dump、加载和重建另需时间。因此不承诺固定吞吐量，更不把单次一小时镜像操作作为批量工作流。

## 放弃或未证实的路线

- 真机镜像逐条人工操作：用户明确认为过慢，批量改用电脑 ADB；必要恢复才人工观察。
- 仅靠无限滚动/固定滑动次数：有慢加载误判底部和年月惯性，改逐月 OCR，重复稳定到底仍属推断需审计。
- 先前 `--retry-server-only` 删除 records 再插回：不保留为公共入口，新入口状态重排而不删除。
- 个人信息官方导出：会话中确实探索过，但现存证据不足以证明导出含轨迹坐标，不编造成功步骤。
- 百度鹰眼开发者导出 API：不等价消费者个人足迹；不新增 service_id、Cookie 或账户抓取途径。
- 旧 TrajectoryCombine：处理旧导航二进制，当前 UUID CSV 未采用其可执行文件。
- `run-as`、Root、绕过 Android 权限：未采用，访问失败即停止。
